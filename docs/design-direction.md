## 설문 요약

- **대면이 채팅 회의보다 나은 영역**: 복잡한 내용 설명 −1.73 (15명 전원 대면), 아이디어 회의 −1.67, 문제 해결 −1.60, 의견이 갈린 상태에서 결정 −1.40
- **채팅이 조금 나은 영역** (유의하지 않음): 역할분담·일정 +0.6, 결정사항 사후 확인 +0.47. 기록이 남고 시간 제약이 없어서.
- **대면이 나은 이유** (Q9): 즉각적 반응 7명, 비언어 신호·오해 방지 6명
- **채팅 회의의 문제** (Q11, 0~3점): 몇몇만 말함 2.47 (14명이 자주 이상), 답장 지연 2.33, 같은 내용을 다르게 이해함 1.67, 결론이 났는지 애매함 1.53. 가장 불편한 것(Q12)은 답장 지연과 몇몇만 말함이 각 5명으로 공동 1위.
- **이해 불일치**: 15명 전원이 결정 내용을 서로 다르게 이해한 경험이 있음(Q14). 어긋난 부분은 결정 내용 자체 9명, 용어 4명, 마감·우선순위 각 3명(Q15). 10명이 작업을 시작한 뒤에야 알았음(Q16).
- **모르는 걸 공개적으로 묻지 않음**: 흐름을 끊기 싫어서 8명, 나만 모르는 것 같아서 6명(Q17). 개인 메시지로 따로 물어봄 10명, 이전 메시지를 다시 읽음 8명(Q18).
- **AI는 이미 개인적으로 씀**: 15명 전원이 회의 전후로 써 봤고 11명은 자주 씀(Q19). 아이디어·의견 정리 15명, 자료 조사 14명, 내 메시지 다듬기 11명(Q20).
- **원하는 AI 역할** (Q21, 1~5점): 비공개 개인 비서 4.27, 자료 먼저 찾아 공유 4.2, 선택지 장단점 4.0. 낮음: 말 적은 사람에게 발언 기회 주기 3.07, 주제 이탈 되돌리기 3.07 (둘 다 의견이 갈림).
- **AI 참여 우려** (Q22): 요약·제안의 품질과 신뢰성, AI가 주체가 되는 것, 개입 타이밍과 정보 과다, 정보 유출.

## Gap → 설계 방향

| Gap (설문) | 설계 방향 |
|---|---|
| ① 아이디에이션은 대면 선호 (−1.67), 일정 정하기는 채팅 선호 (+0.6) | 채팅에서 아이디에이션을 보조 |
| ② 결정 이해가 어긋나고 작업 후에야 앎 (10명), 흐름 끊기 싫어 안 물어봄 (8명) | 해소 시점을 회의 중으로 앞당김 |
| ③ AI를 아이디어 정리에 씀 (15명), 개인 비서를 가장 원함 (4.27/5) | Personal Agent = 범용 개인 비서 |
| ④ 몇몇만 말함 (2.47/3), 공개 발언 유도는 싫어함 (3.07/5) | 개인 창에서 비공개로 묻고 합의 |

## 구성

- 그룹 채팅 + 개인 창 (나와 내 Personal Agent만 봄)
- **Moderator** (방에 1개): 그룹 채팅만 봄. 단계 진행, 촉진, 합의 확인
- **Personal Agent** (사람당 1개): 그룹 채팅 + 개인 대화를 봄. 범용 비서, [채팅에 공유] 버튼
- Moderator 는 개인 대화를 볼 수 없어서, 아직 공유되지 않은 생각을 알려면 Personal Agent 에게 물어야 함

## 흐름

1. **아이디에이션**: 각자 개인 창에서 Personal Agent 와 아이디어를 생각하고, 좋은 건 바로 채팅에 공유.
   - 빠진 관점 꺼내기: Moderator 가 그룹에 없는 관점을 Personal Agent 들에게 물어봄. 해당하는 Personal Agent 는 관점만 답하고(내용은 안 보냄), 자기 사용자에게 "이거 아직 안 나온 관점이야, 공유할래?"를 비공개로 제안.
   - 바로 반응하기: 누가 아이디어를 올리면 각 Personal Agent 가 자기 사용자의 생각 중 연결되는 걸 찾아 덧붙이기를 제안 (답장 초안 포함).
2. **합의**: Moderator 가 합의 시점을 잡고 각자의 개인 창에 확인 메시지를 보냄.
   - 이해가 다르면 Moderator 가 그룹에 익명 질문 1개.
   - 전원이 합의해야 다음 단계로. 그룹에는 "합의 3/4"처럼 숫자만 보여주고 누가 안 했는지는 공개하지 않음.

## 시나리오 (팀 프로젝트 주제 정하기, 4인)

1. A와 B가 아이디어를 공유. C와 D는 조용함.
2. Moderator 가 공공 데이터 관점이 빠졌다는 걸 확인하고 Personal Agent 들에게 물어봄. C의 개인 창에 "아까 정리한 캠퍼스 혼잡도 아이디어, 공유할래?"가 뜨고, C가 공유.
3. D의 Personal Agent 가 D가 찾아본 와이파이 데이터와 C의 아이디어를 연결해서 제안하고, D가 덧붙임.
4. 합의 확인에서 D만 범위를 "캠퍼스 전체"로 이해. Moderator 가 익명으로 범위를 묻고, 팀은 "도서관·학식당"으로 정함.
5. 4/4 합의 후 역할 분담 단계로 넘어감.
